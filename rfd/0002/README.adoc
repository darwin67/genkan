= RFD 2 Animated 4K greeter wallpaper

== Goal

Offer full-screen animated wallpaper while preserving responsive login
controls, readable foreground content, deterministic preview evidence, and
reliable startup in the greetd environment. Media is downloaded only on explicit
request; an unprovisioned installation keeps the generated background.

The first implementation used the original-resolution 4K Tahoe Beach and
Sequoia Sunrise, Morning, and Night wallpaper videos rather than downscaling
them to 1080p. Playback is a presentation concern only; it must not affect
authentication, account discovery, session selection, or power operations.

Implementation progress is tracked in
link:IMPLEMENTATION.adoc[the implementation checklist].

== Context

RFD 1 deliberately retained a generated background and deferred final wallpaper
selection until artwork provenance, packaging, and behavior could be reviewed
together. The generated canvas is technically animated in production, but its
three large translucent circles move through a roughly seven-minute cycle and
have flat, visibly overlapping edges. Development preview freezes elapsed time
at zero so screenshot evidence remains deterministic. Consequently, `make dev`
does not demonstrate motion and the production result does not resemble a
photographic macOS aerial wallpaper.

Apple ships its recent wallpapers in two materially different forms:

* HEIC dynamic wallpapers contain still variants selected by appearance or time
  of day. They do not provide continuous camera or environmental motion.
* MOV aerial wallpapers contain continuous video and can provide the intended
  animated login background.

The evaluated reference downloads are:

* https://mrmacintosh.com/download-the-new-macos-tahoe-wallpaper-desktop-pictures-5k/[macOS Tahoe wallpaper downloads], including the 170.2 MB Tahoe Default Beach MOV;
* https://mrmacintosh.com/download-the-new-macos-sequoia-wallpaper-desktop-pictures-5k/[macOS Sequoia wallpaper downloads], including the 171.9 MB Sunrise, 368.4 MB Morning, and 432.5 MB Night MOV files; and
* https://basicappleguy.com/basicappleblog/dynamic-tahoe-wallpapers[Basic Apple Guy's dynamic Tahoe wallpapers], which package Dawn, Day, Dusk, and Night stills in HEIC rather than continuous video.

These pages mirror or derive their downloads from artwork shipped with macOS;
they are reference and acquisition sources, not evidence of an open-content
license. The selected asset and its exact origin, hash, media metadata, and
packaging treatment must be recorded before implementation is marked complete.

== Decision

Genkan supports a silent looping video as the bottom layer of the greeter.
The initial asset catalog contained the original 4K Tahoe Default Beach MOV and
all three original 4K Sequoia MOV variants: Sunrise, Morning, and Night. Tahoe
Beach remains the default selection because it most directly continues RFD 1's
Tahoe reference, but it must be explicitly cached before it can play. The
catalog now also includes other aerial MOVs and dynamic HEICs. An administrative
setting selects local media; login and lock do not accept remote playback URLs.
Original downloads are not downscaled to reduce storage or transfer size.

The implementation may remux a file without changing its encoded video, but it
will not initially reduce spatial resolution, frame rate, or visual quality.
Any later transcode is accepted only with side-by-side evidence that it avoids
visible degradation on a 4K output and materially improves compatibility or
runtime cost.

Each source is inspected to determine whether its final and initial frames form
a visually seamless loop. A seamless source seeks directly to its beginning. A
non-seamless source holds its final frame while seeking and crossfades that
frame over the newly decoded opening frames. Playback then continues; Genkan
never exposes a hard end-to-start jump. Loop boundaries use the actual stream
duration; crossfade policy remains asset metadata so each video can use
independently verified transition values.

The wallpaper fills the output using aspect-preserving cover semantics: scale
until both dimensions are covered, center the frame, and crop overflow. Genkan
does not stretch the image or expose letterboxing. The existing darkening layer
remains above the video and below all controls so foreground contrast does not
depend on a favorable frame.

[source,text]
----
+--------------------------------------------------------------+
|  looping 4K video, scaled to cover and center-cropped         |
|  +--------------------------------------------------------+  |
|  | uniform contrast-preserving darkening layer            |  |
|  |  +--------------------------------------------------+  |  |
|  |  | clock, identity, authentication, session, power  |  |  |
|  |  +--------------------------------------------------+  |  |
|  +--------------------------------------------------------+  |
+--------------------------------------------------------------+
----

== Playback architecture

Genkan will use GStreamer through its Rust bindings. It will construct the
pipeline through the library API and receive decoded frames through `appsink`;
it will not invoke `gst-launch`, FFmpeg, a shell, or an external media player.
The pipeline disables audio, decodes video asynchronously, converts frames to a
pixel format accepted by iced, and seeks to the beginning at end of stream.

A bounded latest-frame handoff separates media callbacks from the iced update
loop. The decoder may replace an unconsumed frame, but it may not queue an
unbounded sequence or block authentication event handling. The iced thread
uploads at most the newest frame and requests redraw only when a new frame is
available. Output resizing recomputes cover geometry without restarting
playback.

[source,text]
----
cached MOV -> GStreamer decode -> latest-frame slot -> iced texture
                                                        |
selected poster ----------------------------------------+
                                                        |
generated fallback -------------------------------------+
                                                        |
                                                        v
                                             darkening layer and UI
----

GStreamer plugin and codec requirements become explicit Nix runtime
dependencies. The package must work without relying on a desktop session's
environment or per-user plugin installation. Hardware decoding is desirable
but not required for correctness; the same package must retain a software
decode path for supported systems and CI.

The first-frame deadline is bounded. Until a decoded frame arrives, Genkan
renders the selected static poster. A failure before the first frame keeps that
poster and produces a diagnostic that contains no credentials or user-controlled
media metadata. If the poster is missing or cannot be decoded, the existing
generated background remains the fallback. After playback begins, a stream,
seek, device, or allocation failure retains the last displayed frame.
Presentation failures do not close the greeter or disable any interaction.

== Asset and packaging model

Production packages install only the catalog manifest under
`share/genkan/wallpapers`: no MOVs, HEICs, posters, or prepopulated cache. Nix
builds and the development shell do not fetch upstream artwork. Source JPEGs
remain test-only visual references, and authored MOV/HEIC fixtures exercise the
decoders without making third-party artwork a production dependency.

The original design delivered hash-named objects from a Cloudflare R2 bucket as
Nix fixed-output inputs. That delivery model is superseded: code and packaging
no longer depend on R2, and the existing bucket is left untouched. The manifest
now records upstream URLs, cryptographic pins, byte sizes, provenance, media
metadata, and loop policy. Provenance is not an assertion of an open-content
license.

=== Explicit downloads

`genkan assets download <key>` explicitly acquires an original from the curated
upstream catalog; `--catalog sources.toml` selects replacement
`[assets.<key>]` tables. `download <key> --url URL [--sha256 HASH]` supports a
custom source but cannot replace a key in the selected catalog. Transfers
require a direct HTTP(S) response with status 200 and reject redirects. The
default `--max-bytes` is 2 GiB, configurable from 4 KiB to 16 GiB, and bounds
both transfer and expanded media. Each transfer times out after 600 seconds.

Download preparation, including hashing and ZIP parsing, runs with resource and
time limits. The downloader verifies declared byte sizes and SHA-256 hashes,
then validates a representative HEVC MOV or HEIC frame before publication.
A configured ZIP source must pin the archive and the exact media member;
only that member is extracted to a controlled filename, never an archive path.
A MOV download generates a poster. Observed format, dimensions, size, and hash
persist in `entries/<key>.toml` so custom downloads appear in later list/preview
commands. Without a trusted custom SHA-256, the recorded hash identifies the
download but does not authenticate its upstream origin. Frame validation is not
a promise that every frame decodes.

=== Local cache and overrides

The cache root is the absolute `GENKAN_WALLPAPER_DIR`, otherwise an absolute
`XDG_CACHE_HOME` plus `/genkan/wallpapers`, otherwise an absolute `HOME` plus
`/.cache/genkan/wallpapers`. A relative override is an error. Each receipt
selects one complete downloaded generation:

[source,text]
----
cache-root/
  entries/<key>.toml                 (atomic generation selector)
  objects/download-<key>-<random>/
    <key>.mov or <key>.heic
    <key>-poster.jpg                (MOV only)
    entry.toml                      (metadata and hashes)
    published                       (retention marker)
  mov/ and heic/                    (explicit local/test provisioning only)
----

Only after preparation succeeds does an atomic receipt replacement publish the
media, poster, and metadata together. The generation is marked published before
the receipt switch, and readers select one receipt snapshot for all three.
Preparation and publication failures leave the previous generation usable.
This is not a promise of simultaneous display changes across processes or
filesystem durability after power loss.

Conventional `mov/` and `heic/` directories remain supported for explicitly
provisioned local/test files, not as downloaded-media destinations. Use the
absolute media path printed by download with `--wallpaper-file`, rather than
constructing a path. Published generations are retained so in-flight previews,
deferred HEIC opens, and saved absolute overrides remain valid. Replacements may
occupy additional disk space; remove an unused version only when no readers or
saved overrides need it.

=== Provisioning and recovery

Operators must explicitly provision the greeter's cache under its own identity
or set a shared absolute override; a desktop user's cache is not automatically
available to greetd. Login, lock, previews, and wallpaper playback never download
missing media. An empty cache uses the generated background; `assets preview`
instead reports the missing file.

SIGINT or SIGTERM stops preparation and cleans staging. After SIGKILL or a
crash, the next explicit download cleans only abandoned, unpublished staging
under the cache lock, never previously published generations. Playback never
performs cleanup. Cancellation or a preparation timeout does not publish partial
media.

Development and production accept an administrative wallpaper path so exact
media can be tested without copying it into the repository. The path
override is opened and validated once, then passed to GStreamer by descriptor
so a later pathname replacement cannot change the media being decoded. It is a
file path only, not a URI: network schemes, playlists, and GStreamer pipeline
descriptions are not accepted.

== Preview and configuration behavior

Ordinary preview remains deterministic. It does not start the decoder and
renders the cached poster, with the generated background as a fallback when
that poster is unavailable. Automated reference captures use an explicit
test-only cache of source JPEGs, not a production fallback.

A separate animated-preview option enables real playback for local review. It
does not unfreeze the fixture clock, contact AccountsService, greetd, or logind,
or make simulated authentication and power actions real. The distinction must
be visible in `--help` and documented next to `make dev`.

`genkan assets list` prints the upstream MOV and HEIC catalog plus cached custom
entries with dimensions, size, and local availability.
`genkan assets preview <id>` opens the existing windowed animated login preview
for a cached asset, with optional
`--appearance light|dark` for HEIC and `--reduce-motion`. It downloads nothing,
changes no configuration, and never acquires a session lock. Closing the window
ends the preview; missing assets fail with their expected local path and a
download instruction. `--catalog` selects the same replacement catalog for
list, preflight, download, and preview.

=== Optional preflight

`genkan assets preflight <key>` inspects an original source using bounded HTTP
range reads, outside login and lock. Users may replace the curated metadata
with `[assets.<key>]` TOML tables, or supply a key and `--url` directly. The
isolated worker decodes one representative frame with the existing media
libraries and reports passed, unsupported, or inconclusive. Incomplete reads,
unstable versions, and unsupported range delivery never imply compatibility
or initiate a full download. Missing strong ETags and ZIP sources can produce
inconclusive or unsupported results without preventing an explicit download:
that command performs complete-file integrity checks and local frame validation
independently. Inspection installs nothing and does not change selection.
Apple's root certificate is used only for curl requests to the exact HTTPS
aerial host `sylvan.apple.com`, not added to system trust; peer and hostname
verification remain enabled.

=== Playback defaults

The production default plays animation when the selected media is cached;
otherwise it uses the generated background. An administrative reduced-motion or
static setting shows the poster frame without initializing GStreamer. Decode
failure before the first frame has the same visual result but is reported
separately so operators can distinguish preference from failure. A later
failure retains the last displayed frame.

== Performance and resource boundaries

Keeping the source at 4K preserves detail on native 4K displays but does not
require rendering hidden pixels at all output sizes. GStreamer may scale decoded
frames to the current cover target before CPU-to-GPU transfer. Genkan retains at
most the displayed texture, one pending frame, decoder-owned working memory,
and the static fallback; application code does not retain prior frames.

Acceptance is based on measured behavior rather than an assumed hardware decode
path. On the software Vulkan CI path and the available physical graphics hosts,
playback must not starve keyboard input, delay PAM prompt transitions, grow
memory over repeated loops, or terminate when seeking. Frame drops are
preferable to queuing stale frames or delaying interaction.

== Accessibility and contrast

Motion remains behind all controls and does not encode state or instructions.
The static setting provides equivalent information because the video is purely
decorative. The global darkening treatment must satisfy the existing text,
focus, boundary, dialog, and menu contrast targets across representative bright
and dark frames from the selected video.

The current generated-background contrast model is not sufficient evidence for
photographic video. Tests will sample at least the brightest, darkest, and
highest-local-contrast retained frames, including frames behind each major
foreground region. Renderer-aware compositing checks remain the numeric source
of truth; screenshots support visual review without replacing those checks.

== Security and failure boundaries

The wallpaper decoder runs before authentication and processes only local
media: a previously downloaded, validated catalog asset or an explicit local
override. Media bytes, tags, paths, decoder output, and errors never enter greetd
requests or logs containing PAM responses. The
feature does not broaden session-command discovery, invoke a shell, read account
icons, or transfer authentication ownership away from greetd.

An invalid administrative path, unsupported codec, missing plugin, corrupt
stream, unavailable hardware decoder, or failed loop seek is a presentation
failure. Genkan records a bounded diagnostic, releases failed playback
resources, and keeps the initial poster or generated background until the first
frame. Once playback has begun, it retains the last displayed frame. Decoder
retries are bounded so a permanently invalid asset cannot create a busy loop.
Administrative overrides are first bound with Linux `O_PATH` and validated as
regular files without opening the target for I/O, so a pathname changed to a
FIFO, device, or another special file cannot stall startup. The bound inode is
then reopened through `/proc/self/fd` and passed to GStreamer, so later pathname
replacement cannot substitute another file.

== Verification

The implementation must provide evidence for:

* metadata and cryptographic identity of curated upstream sources;
* an artwork-free production package and usable offline empty-cache startup;
* explicit download integrity checks, bounded frame validation, configured ZIP
  extraction, generated MOV posters, and persistent custom metadata;
* atomic generation publication, previous-generation recovery on failure, and
  interrupted-download cleanup without playback-side cache mutation;
* deterministic static preview with no media decoder or service connections;
* animated preview producing distinct valid frames while keeping fixture time
  and simulated side effects fixed;
* successful cover scaling at laptop, 1080p, 4K, ultrawide, and narrow output
  dimensions;
* continuous looping without a visible end-to-start jump or unbounded memory
  growth for every catalog entry;
* responsive keyboard, authentication, and modal interaction during software
  decoding;
* fallback behavior for missing media, missing plugins, decode failure, and
  failed seek;
* contrast over representative retained video frames and all existing control
  states; and
* packaged launch under nested Cage plus physical AMD/NVIDIA validation where
  connected outputs are available.

The existing real-greetd end-to-end test remains required because playback must
not alter PAM failure recovery, successful authentication, or session startup.

== Alternatives considered

=== Keep the generated canvas

This has no media dependencies and already degrades safely, but its flat color
fields do not meet the desired animated-wallpaper appearance. It remains the
runtime fallback rather than the primary presentation.

=== Use a dynamic HEIC

HEIC variants provide day, dusk, and night changes with much smaller assets,
but they are still images rather than continuous animation and add a separate
metadata interpretation and decoder path. They were deferred at the original
decision and are now supported as a separate time-of-day mode, not a substitute
for continuous MOV animation.

=== Downscale to 1080p

This reduces decode and package cost but visibly sacrifices detail on a 4K
output. The initial implementation retains original resolution and measures the
actual cost before accepting that tradeoff.

=== Recreate the appearance with a shader

A procedural shader is compact and avoids media decoding, but it would create a
different abstract animation instead of the selected photographic aerial. It
does not satisfy the decision to use the available reference video.

=== Delegate playback to the compositor

Cage intentionally provides a narrow kiosk environment and does not own
wallpaper policy. Adding another process complicates layering, startup,
failure handling, and lifecycle ownership. Genkan owns its decorative layer and
keeps compositor configuration independent.

== Non-goals

This RFD does not add audio, remote playback URLs, playlists, an in-greeter wallpaper
browser, lock-screen behavior, per-account media, arbitrary GStreamer pipeline
input, or desktop-session wallpaper configuration. It does not change greetd,
PAM, AccountsService, session validation, or logind behavior.
