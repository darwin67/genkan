#+TITLE: RFD 0001 implementation checklist
#+STARTUP: showall

Implements [[file:README.adoc][RFD 1: Tahoe-inspired greeter interaction and visual design]].

* Baseline and acceptance evidence

- [X] Record that the pre-layout preview was not retained before layout work
  began and cannot be reconstructed as historical acceptance evidence.
- [X] Record durable reference screenshots for account selection, a secret
  prompt, a visible prompt, failed authentication, power confirmation, and
  narrow layout; generated CI evidence is intentionally not a pixel contract.
  See [[file:ACCEPTANCE.adoc][acceptance evidence]].
- [X] Define reviewable acceptance checks for hierarchy, focus order, wrapping,
  WCAG contrast targets, and notice placement without treating screenshot
  pixels as the behavioral contract.
- [X] Add deterministic preview fixtures for zero/one/many, duplicate-name, and
  large account sets; secret/visible and consecutive informational prompts;
  failure sources; cancellation progress; and power confirmation.
- [X] Prove preview never contacts AccountsService, greetd, or logind and never
  retains a simulated response after submission or account change.

* Interaction model

- [X] Represent account selection and selected-account authentication as clear
  presentation states derived from the existing authentication lifecycle.
- [X] Load AccountsService ~LoginTime~ and directly select the unique most
  recently logged-in eligible account, falling back to the sole eligible account
  or account selection when recency is unavailable, zero, or tied; treat a
  ~LoginTime~ read failure as unknown recency rather than an ineligible account.
- [X] Test override precedence, unique recency, tied/zero/unknown recency, a sole
  account, and deterministic account ordering without persisting a second
  last-user record.
- [X] Preserve cached, valid, unlocked, non-system account eligibility and
  partial object-failure behavior.
- [X] Present eligible identities in a wrapped, scrollable avatar grid with a
  visible username for every tile.
- [X] Record unique semantic account names as a framework-bound follow-up until
  iced exposes a supported accessibility tree; visible text and
  application-managed keyboard focus are retained without claiming equivalence.
  See the upstream availability criteria in
  [[file:ACCESSIBILITY.adoc][accessibility verification]].
- [X] Keep the selected identity prominent during authentication and provide a
  Change User action whenever another eligible identity can safely be selected.
- [X] Make Change User immediately invalidate the attempt, clear the response,
  and display account selection while a noninteractive state cancels greetd.
- [X] Disable tile activation until cancellation succeeds; on slow cancellation
  show stable progress, and on failure offer retry without calling
  ~CreateSession~ or resurrecting the invalidated attempt.
- [X] Test exact ~CancelSession~ before ~CreateSession~ request ordering,
  cancellation failure and retry, repeated Change User, and stale responses.
- [X] Preserve direct selected-account startup for administrative username
  overrides without AccountsService discovery or Change User, and preserve the
  safe development preview.

* Authentication presentation

- [X] Render secret, visible, informational, and error PAM messages without
  assuming a single password prompt.
- [X] Automatically acknowledge noninteractive protocol messages while keeping
  the latest one visible until the RFD-defined superseding event; test
  message-to-prompt and consecutive-message sequences.
- [X] Keep prompt, input, submit action, progress, and inline failure feedback
  together as one compact readable unit.
- [X] Represent account, session, authentication, greetd transport/session,
  power, and preview notices by source and place each according to the RFD table.
- [X] Preserve input focus across recoverable prompt transitions, preserve an
  entered response through power confirmation, and restore focus to the dialog
  opener without accepting input in inactive phases.
- [X] Verify failed authentication can retry or change account without
  restarting Genkan.

* Visual hierarchy

- [X] Remove the enclosing login panel and place time/date, identity flow,
  session choice, and utilities in the RFD hierarchy.
- [X] Establish shared styling for avatar tiles, compact prompt controls,
  selectors, utility actions, focus rings, and confirmation dialogs.
- [X] Use translucent material only for functional controls and focused
  surfaces, with a contrast-preserving background treatment.
- [X] Keep the generated background and leave final packaged wallpaper artwork
  to a separate provenance and packaging review, as defined by the RFD non-goal.

* Input and accessibility

- [X] Define and test keyboard focus order for account selection, prompt input,
  submit, Change User, session selection, and utility actions.
- [X] Test state-specific initial focus, Enter/Space activation, Escape behavior,
  modal focus containment, safe initial modal action, and focus restoration.
- [X] Ensure every icon action has a visible text or accessible label and no
  action depends only on hover, color, or icon recognition.
- [X] Exercise pointer, keyboard, and touch-equivalent account activation where
  iced and the test environment expose those paths.
- [X] Verify long localized prompts and bounded account labels wrap without
  hiding the current input or status.
- [X] Record unique accessible account names and status announcements as
  follow-ups for an iced release that meets the semantic-tree, Linux adapter,
  and selective-announcement criteria in
  [[file:ACCESSIBILITY.adoc][accessibility verification]].
- [X] Define the numeric contrast boundary as renderer-aware tests over 125
  representative generated background combinations, control states, and bright
  underlays without claiming exhaustive continuous-antialias coverage.
- [X] Verify those contrast targets over 125 representative generated background
  combinations, both iced blend spaces, and bright overlay underlays; see
  [[file:ACCESSIBILITY.adoc][accessibility verification]].

* Session and power controls

- [X] Move the validated Wayland session selector to the lower-left secondary
  position without changing its command-validation boundary.
- [X] Add only implemented keyboard and accessibility utility controls; do not
  render placeholders.
- [X] Place labelled power actions in the utility area and preserve explicit
  confirmation, logind error reporting, and preview simulation.

* Responsive and graphics verification

- [X] Verify the composition at common laptop, 16:9, ultrawide, and narrow
  dimensions without relying on one fixed screenshot geometry.
- [X] Add deterministic view-model or widget-state regressions for selection,
  authentication, account switching, disabled controls, and wrapped content.
- [X] Run ~make verify~ on x86_64-linux and the packaged graphics smoke check on
  both x86_64-linux and aarch64-linux; do not treat ARM graphics smoke as full
  ARM verification. Both native CI jobs passed for [[https://github.com/darwin67/genkan/pull/11][PR #11]].
- [X] Run ~make e2e~ to verify real greetd/PAM failure recovery, successful
  authentication, and session environment behavior after lifecycle changes.
- [X] Run ~make hardware-smoke~ on available connected AMD/NVIDIA outputs for
  physical presentation evidence; retain host suspend/resume as an independent
  kernel and display-stack concern. The Framework Radeon 890M and its connected
  eDP/DP outputs passed; the RTX 5070 passed Vulkan discovery and has no connected
  DRM output on this hybrid-display topology.
